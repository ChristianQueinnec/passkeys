Passkeys User Guide

Version 0.2.0 | January 2025

Introduction

Passkeys is a secure, cross-platform password manager accessible through any modern web browser. Unlike platform-specific tools like KeePass, Passkeys works identically on macOS, Linux, Windows, Android, and iOS.

The original idea comes from Manuel Serrano who designed such an application in Bigloo around 2010. The idea was to decipher the passwords in the browser, the server storing only ciphered information while being unable to decipher them.

The desire to find a project to which I can experiment Vibe Coding makes me revive that idea. The Passkeys project was born.

Core Features

Security: Client-side AES-GCM encryption ensures the server never sees your unencrypted data. Your vault key stays in your browser.

Accessibility: Progressive Web App (PWA) works online and offline. Install it on any device for native-like experience.

Organization: Hierarchical folder structure with tags and full-text search across all fields.

History: Automatic versioning lets you restore previous vault states.

Auto-Security: The inactivity timeout clears decrypted data, and copied credentials are auto-cleared. Quick unlock accepts a requested minimum prefix or suffix, including longer values only when they match the vault key exactly.

Security Model

Passkeys uses two separate credentials:

  1. Login Password: Authenticates you to the server (stored as scrypt hash)
  2. Vault Key: Decrypts your vault in the browser (never transmitted)

This separation ensures server compromise cannot expose vault contents.

Using the Web Application

First Login

  1. Navigate to your Passkeys instance (e.g., http://localhost:3000)
  2. Enter username and password
  3. Toggle eye icon to reveal/hide the password
  4. Press Enter or click Login

Unlocking Your Vault

After authentication, provide your vault key:

  1. Enter the passphrase that encrypts your vault
  2. Toggle eye icon to reveal/hide the key
  3. Press Enter or click Unlock

First-time users: See dedicated section below

Managing Entries

Viewing

Folder View: Hierarchical tree navigation with expandable folders List View: Flat, filterable list of all entries Toggle: Switch between views using the view selector

Search and Filter

Type in the search box to filter entries by: - Title - Username - Site URL - Tags - Notes

Search is case-insensitive and matches partial text.

Entry Details

Click any entry to view: - Title: Entry name - Username: Click to copy - Password: Masked; click to copy - Site: Click to open URL in another tab or window - Tags: Keywords for organization - Notes: Additional information - Group: Folder path

Copied credentials auto-clear from clipboard after 10 seconds.

Create Entry

  1. Click Add Entry button
  2. Fill required fields:
  • Title (required)
  • Username
  • Password
  • Site URL
  • Group (folder path, e.g., Work/Email)
  • Tags (space or comma-separated)
  • Notes
  1. Click Save

Edit Entry

  1. Click entry to open
  2. Click Edit
  3. Modify fields
  4. Click Save

The username field is an editable combo box. It suggests only email addresses that occur in at least two other entries, while still allowing a different username to be typed. The password field includes Generate password, which creates a password in the form XXXX-XXXX.XXXX;XXXX=XXXX. Generated characters are letters and numbers chosen to avoid ambiguous glyphs such as O, 0, I, l, 1, and i.

Delete Entry

  1. Click entry to open
  2. Click Delete
  3. Confirm deletion

Saving Changes

Modified vaults show a "Save Vault" button. Click it to encrypt and upload changes to the server.

Vault History

Access previous vault versions:

  1. Click History button
  2. View timestamped versions with file sizes
  3. Restore: Revert to selected version
  4. Delete: Remove old versions

Unciphered vaults stored in the server are displayed accompanied with a warning to remind the user to remove these unciphered vaults as soon as possible once downloaded and ciphered in a browser and saved on the server.

Paramètres des délais de sécurité

Depuis le menu utilisateur, vous pouvez modifier en minutes le délai de verrouillage après inactivité et la durée de disponibilité du déverrouillage rapide. Sur un appareil sûr, ces valeurs sont conservées localement ; sur un appareil non sûr, elles ne s appliquent qu à la session en cours.

Offline Mode

Passkeys caches encrypted vaults locally:

  • Vault accessible without connectivity
  • Offline indicator warns data may be stale
  • Changes require online connection to save

Messages and Warnings

Toast messages, including warnings and errors, have a close button so they can be dismissed immediately. Persistent notices such as offline status remain visible while the underlying condition applies.

Security Features

Auto-Timeout: After 60 seconds idle, decrypted vault clears from memory. Re-enter vault key to access.

Clipboard Protection: Copied credentials auto-clear after 10 seconds.

Session Management: Logout clears session tokens and decrypted data.

Easiest Installation

Prerequisites

  • Node.js >= 22.13
  • Git

Quick Start

# Clone repository
git clone https://github.com/ChristianQueinnec/passkeys.git
cd passkeys/
npm install
./scripts/init.sh -u -v -e
. ./.env && npm run preview

This will create a user (see data/users.json) with your login name and a generated password. Read the output of the script and memorize the generated password to access the vault (you may change it later). Really memorize this information since it will be hashed on first server start and no longer readable.

An initial vault is also created with example password entries. A me entry holds your login information.

You can end your session with CTRL-c. You may restart the server with your previous vault preserved with

. ./.env && npm run preview

If coming from Keepass, transfer your passwords as follows:

# Export from Keepass your passwords in CSV
KeePass2Passkeys/csv-to-json.ts YOUR.csv data/${USER}/vault-from-keepass.vault
# Within Passkeys:
#  -1- History, download vault-from-keepass.vault
#  -2- save to server
#  -3- History, delete vault-from-keepass.vault

Server Deployment and Storage

The server administrator can store vault revisions either in the local data/ directory or in Google Drive. This choice does not change the client application: vaults are encrypted in the browser before they are uploaded.

The default is the local filesystem. To use Google Drive, configure the server with:

STORAGE_PROVIDER=google-drive
GOOGLE_DRIVE_FOLDER_ID=optional-parent-folder-id
GOOGLE_DRIVE_CLIENT_ID=...
GOOGLE_DRIVE_CLIENT_SECRET=...
GOOGLE_DRIVE_REFRESH_TOKEN=...

The Drive account must be allowed to access the parent folder. Passkeys creates a separate folder for each user and stores vault history as .vault files. The server-side data/users.json file remains local because it contains login credentials and is not part of vault storage. An access token can be used for testing, but a refresh token is required for a long-running deployment.

Quick Start

Finally, the server is built as a Docker container and run. Kill it with CTRL-c.

Using the Initialization Script

The scripts/init.sh script automates setup:

# Create test setup (admin/password)
./scripts/init.sh -t

# Create production setup with generated password
./scripts/init.sh -u -v

# Full initialization and server start
./scripts/init.sh -i

Options: - -u: Create users.json - -v: Create sample vault - -e: Create .env file - -b: Build and run container - -i: Full initialization (equivalent to -e -u -v -b) - -t: Test mode (admin/password credentials) - -r: Run server

Examples:

# Test environment
./scripts/init.sh -t -r

# Production initialization
./scripts/init.sh -i

Build and Run

Method 1: Using Make (Recommended)

# Build container with proper user permissions
make create.container

# Run container
make run.container

Access at: http://localhost:3000

The Makefile handles: - Image tagging with timestamps - User ID/Group ID mapping - Container registry management

Method 2: Using Docker Compose

# Build and run
docker compose up --build -d

# View logs
docker logs -f passkeys

# Stop
docker compose down

Docker Compose Configuration

Example docker-compose.yml:

services:
  passkeys:
    build:
      context: .
      args:
        UID: 1001
        GID: 1001
        USER: passkeys
    container_name: passkeys
    ports:
      - "3000:3000"
    volumes:
      - ./data:/app/data
    restart: unless-stopped
    environment:
      - NODE_ENV=production

Configuration Notes: - UID/GID: Match host system for file permissions - volumes: Mount local data/ directory - ports: Expose port 3000 for web access - restart: Auto-restart on failure - For Google Drive storage, pass the STORAGE_PROVIDER and GOOGLE_DRIVE_* variables to the container and keep the local data/ volume for users.json and server state.

Environment Variables

Create .env for JWT secret:

# Generate secure JWT secret
cat > .env <<EOF
export JWT_SECRET=$(openssl rand -hex 32)
EOF
chmod +x .env

Or use initialization script:

./scripts/init.sh -e

Security Configuration

File Permissions: Restrict data/ directory:

chmod 700 data
chmod 600 data/users.json

Firewall: Limit port 3000 to trusted networks

HTTPS: Use reverse proxy (nginx, Caddy) for TLS in production

Backups: Regularly backup data/ directory:

tar -czf passkeys-backup-$(date +%F).tar.gz data/

Troubleshooting

Container won't start:

# Check logs
docker logs passkeys

# Verify users.json exists and is valid
cat data/users.json | jq .

# Check port availability
lsof -i :3000

Permission errors:

# Verify ownership
ls -la data/

# Fix permissions
sudo chown -R $(id -u):$(id -g) data/

Cannot decrypt vault: - Verify correct vault key - Check vault file format: cat data/admin/vault-init.vault | jq . - Ensure vault is valid JSON array

Build failures:

# Clean Docker cache
docker system prune -a

# Rebuild from scratch
make create.container

Common Questions

Q: I forgot my vault key A: Vault keys cannot be recovered by design. Create a new vault or restore from backup if you exported one.

Q: Can I change my vault key? A: Yes. Unlock with current key, then save vault—you'll be prompted to encrypt with a new key.

Q: How do I migrate from KeePass? A: Export KeePass to CSV, then use the included KeePass2Passkeys converter tool. It will generate a JSON file you may upload in the browser.

Q: Is Passkeys secure for production use? A: Passkeys uses industry-standard AES-GCM encryption and follows security best practices. However, review the source code and deploy with HTTPS for production.

Q: Can multiple users share a vault? A: No. Each user has separate vaults. Vaults are encrypted with personal vault keys.

Q: What happens if the server is compromised? A: Encrypted vaults remain secure. Attackers cannot decrypt without your vault key, which never leaves your browser.
